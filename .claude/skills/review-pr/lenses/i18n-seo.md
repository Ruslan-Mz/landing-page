# Линза: i18n-seo — языки, адреса, поисковик

Два лица × два языка, четыре адреса плюс алиас `/research/` и `404` (`CLAUDE.md`, правила 4–5). Дефект здесь редко виден глазом: страница выглядит нормально, а поисковик получает редирект вместо адреса, мессенджер — чужое превью, посетитель из РФ — латвийский Telegram.

## Метод

1. **Поля контента.** Новое или изменённое поле `FaceLocale` в `src/lib/content.ts` заполнено в обоих языках обоих лиц, где интерфейс его рендерит. Необязательное поле (`?`) молча пропадает со страницы — проверь, что это задумано.
2. **Адреса.** Все пути — из `pathFor()` / `altsFor()` / `crossFor()` / `abs()`. Путь, вписанный строкой, и путь без слэша на конце — находка: оба хостинга ответят 301.
3. **Посмотри сборку.** Собирает дирижёр, сам не собирай. По `dist/` для каждой из пяти страниц: `<html lang>`, `canonical`, `hreflang` (пара языков одного лица + `x-default`), `og:image` и `og:locale`, JSON-LD. `/research/` — canonical на `/`, в sitemap нет. `404.html` — `noindex`, без canonical и hreflang, в sitemap нет.
4. **Sitemap.** `sitemap-*.xml`: четыре адреса со слэшем, у каждого пара `hreflang`. Встроенная i18n `@astrojs/sitemap` видит язык только по первому сегменту пути — пара `/dev/` ↔ `/dev/ru/` держится на `serialize` в `astro.config.mjs`; новый адрес под `/dev/` нужно добавить туда же.
5. **OG по языку.** Превью выбирается по лицу **и** языку: `/dev/ru/` показывает русскую карточку.
6. **Контакты.** `CONTACTS[face][locale]`: на RU-страницах российский Telegram, на EN — латвийский; почта в подвале — тоже по языку.
7. **Переключатели.** Язык ведёт на ту же страницу в другом языке; переход на другое лицо сохраняет язык.
8. **JSON-LD.** `url` совпадает с canonical, `jobTitle` и `knowsAbout` — своего лица и языка, `sameAs` — только реально существующие профили.

## Вопросы

2. Какое превью увидит русский заказчик, если переслать ему `/dev/ru/` в Telegram?
3. Совпадает ли пара `hreflang` в HTML с парой в sitemap?

## Замечено в этом репозитории

- Встроенная i18n sitemap не распознала `/dev/ru` как русскую пару `/dev` — пары не было, пока не добавили `serialize`.
- Одна OG-картинка на лицо: у `/dev/ru/` было английское превью.
- Telegram был привязан к лицу, а не к языку: на `/dev/` (EN) стоял российский.
- После смены `/dev` с RU на EN старый адрес `/dev/en` исчез — нужен редирект, если ссылку успели раздать.
- Адреса без слэша в canonical и ссылках вели на 301, пока не включили `trailingSlash: 'always'`.
